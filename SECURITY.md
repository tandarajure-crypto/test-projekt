# Security Policy

## Supported Version

Only the current version published from the `main` branch is supported with security updates.

Older downloaded copies, archived versions, forks, and unofficial copies are not supported.

## Reporting a Vulnerability

Please do not report security vulnerabilities through a public GitHub issue, discussion, guestbook, contact form, or public comment.

Use GitHub's private vulnerability reporting feature:

1. Open the repository's **Security and quality** tab.
2. Open **Advisories**.
3. Select **Report a vulnerability**.
4. Describe the vulnerability, the affected file or page, and the steps needed to reproduce the problem.

Please include only the information necessary to investigate the issue.

Do not include passwords, access tokens, private keys, personal identification documents, or unnecessary personal data.

Reports will be reviewed as soon as reasonably possible. Confirmed vulnerabilities will be investigated and corrected before public disclosure whenever possible.

Please allow sufficient time for investigation and correction before publicly disclosing a reported vulnerability.

## Security Scope

Security reports may include:

- Cross-site scripting or unsafe HTML injection
- Malicious redirects
- Exposed passwords, tokens, or private keys
- Compromised third-party scripts or resources
- Unauthorized changes to repository or website content
- Technical exposure of private or personal data
- Bypassing website security controls

The following are not security vulnerabilities:

- Genealogy corrections
- Incorrect names or dates
- Broken links
- Translation corrections
- Design suggestions
- General content updates
